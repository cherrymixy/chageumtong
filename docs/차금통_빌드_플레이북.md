## 0. 시작 전 세팅 (수동, 15분)

### 0-1. 새 프로젝트 만들기 (Android Studio)
1. **New Project → Phone and Tablet → Empty Activity**
2. Name `Chageumtong` · Package `com.pure.chageumtong` · Language **Kotlin** · Minimum SDK **API 28** · Build config **Kotlin DSL**
3. Finish → Gradle sync 끝날 때까지 대기

프로젝트 폴더(Finder에서 `Chageumtong/`)에 이렇게:
```

├─ docs/

├─ app/ ...         (Android Studio가 만든 것)

### 0-3. Git + GitHub
Android Studio 아래 **Terminal**에서:
```
git init && git add . && git commit -m "step -1: empty project + docs"
```
GitHub에서 **Private** 저장소 `chageumtong` 만들고 안내대로 push. (11/16에 Public 전환)

Terminal에서 `claude` 실행 후 `/mcp`로 Figma가 연결돼 있는지 확인. 없으면:
```
claude mcp add --transport http figma https://mcp.figma.com/mcp
```
→ 다시 `claude` 실행 후 `/mcp`에서 인증.

### 0-5. 일러스트 export (승아)
Figma에서 PNG @2x로 export 해서 `app/src/main/res/drawable-nodpi/`에 넣기 (파일명은 영문 소문자_언더스코어):

## STEP 2 — 도메인 엔진 (순수 Kotlin + 테스트)

**목적:** 포인트 규칙을 화면과 무관하게 정확히 만든다. 여기가 틀리면 다 틀려요.

**프롬프트:**
```
STEP 2. domain/ 패키지만 작업해. Android import 금지. 먼저 계획 보여주고 승인 후 진행.

PRD §3, §8 그대로:
- 모델: Gear, DriveState, ViolationType, Violation, DriveSession, PointTx, Product, Place
- 미적립 구간 합집합 계산 (겹치는 구간 병합)
- safeKm, safeRatio, points(floor), 칭찬 문구 함수
- DriveSessionEngine:
  입력 = (timestamp, speedMps, gear) 샘플 스트림 + 현재 구간 정보(제한속도, 커브 여부, 위치 라벨)
  출력 = StateFlow<LiveDrive>(state, distanceKm, durationSec, violations, livePoints)
  · IDLE→DRIVING: gear D && speed>0
  · DRIVING→ENDED: speed==0 && gear P
  · 거리 = 속도 적분 (샘플 간 사다리꼴)
  · 과속: 제한+10km/h 초과 3초 지속 → 1건 (같은 과속 지속 중엔 중복 X)
  · 급커브: 커브 구간 진입 시 속도>40km/h → 1건
  · 안전거리: 외부에서 이벤트 주입 함수 제공 (injectViolation)
  · 0.3km 미만 주행은 ENDED 시 적립 불가 플래그
- JUnit 테스트: 구간 병합, 경계값(0.3km, 정확히 +10km/h), 15.4km/1건 위반 시 포인트,
  과속 지속 중복 방지.
테스트 전부 통과 → git commit "step 2: domain engine".
```

**끝나고 점검:** 테스트 전부 초록. 특히 "17.4km 주행, 미적립 1.0km → 16P"가 나오는지 하나 추가로 물어보기.

**내가 할 것:** 규칙이 기획 의도랑 맞는지만 확인. 코드는 안 봐도 됨.

## STEP 3 — 입력원 (Real / Demo) + 세션 연결

**목적:** 실 SDK와 데모 주행이 같은 엔진을 타게 만들기. 심사위원용 데모의 핵심.

**프롬프트:**
```
STEP 3. data/vehicle/ 와 core/AppContainer 만. 계획 먼저.

- interface VehicleDataSource { val samples: Flow<VehicleSample>; fun start(); fun stop() }
- PleosVehicleDataSource: Vehicle SDK로 속도·기어 구독 → VehicleSample.
  capability 확인 API로 지원 여부 먼저 체크, 미지원이면 isAvailable=false.
  초기화/해제는 문서대로 (Activity/Process 수명주기에 맞게).
- DemoVehicleDataSource: 25km 데모 경로를 90초로 압축 재생.
  · 경로 데이터 data/seed/demo_route.json: 구간별 (startKm, endKm, 제한속도, isCurve, locationLabel)
    + 분석 화면 지도용 정규화 폴리라인 좌표 [(x,y)...] 0~1
  · 7km 급커브(진입 속도 55km/h), 11km 과속(제한 50에 70km/h 5초), 13.5km 안전거리 미확보 주입
  · 시작 시 기어 D → 끝나면 속도 0 → 기어 P
- AppContainer: 두 입력원을 합쳐서 엔진에 공급. 데모 실행 중이면 데모 우선, 아니면 Pleos.
- scripts/drive_demo.sh: adb로 D→가속→정차→P 시나리오를 쏘는 쉘 스크립트 (실 SDK 경로 검증용)
- 임시 디버그 화면(MainActivity 교체): state, 거리, 시간, 포인트, 위반 목록 텍스트 + [데모 주행] 버튼
빌드 → 데모 버튼으로 90초 후 ENDED + 포인트 확인 → scripts/drive_demo.sh로도 확인 → commit.

- 데모: 약 90초 뒤 ENDED, 위반 3건, 포인트 ≈ 23P 근처
- adb 스크립트로도 DRIVING→ENDED 전환이 되는지 (**실 SDK 사용 증명 = 기술 활용성 점수**)

**내가 할 것:** 두 경로 다 눈으로 확인. 이때 화면 녹화 한 번 떠두면 Phase 1 영상 백업이 돼요.
